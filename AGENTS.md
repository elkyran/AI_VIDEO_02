# AI_VIDEO_02

Работать в существующей студии. Сначала читать development/HANDOFF.md,
development/tasks.json и только нужную задачу development/01_DEVELOPMENT_PLAN.md.
Пакеты выполнять только по поручению владельца; после пакета сохранить отчёт и остановиться.

## Режимы

- production: применять config/production_profile.json и существующие операции.
  Новые функции, изменение кода или профиля требуют отдельной development-задачи.
- development: явный T-ID либо отдельно порученный ID дефекта, адресное чтение,
  ограниченные изменения, короткие проверки на временных данных.
- Текущие команды и границы программных проверок: development/INTERFACES.md.
  Эти инструкции сами по себе не блокируют произвольные shell-команды.

## Сохранность

Сохранять Ruslan, отдельные WAV и кеш, Timeline/MLT, реестр, оригиналы и ручные правки.
Не менять модель/голос/формат автоматически. Профиль — единственный источник
технических предпочтений; runtime.json содержит локальные пути исполнения.
Проверять согласованность перед производством, не синхронизировать молча.
Темы и художественные решения остаются свободными в рамках задания владельца.

Не запускать новый выпуск, полный рендер или импорт архива в задачах развития.
Не делать полный аудит и не перечитывать исторические сессии.
Не менять глобальные настройки, не публиковать и не вызывать платные API.
Не использовать reset --hard, clean, eval из заметок или опасную перезапись.
При активной операции не менять её код/базу. SQLite сохранять через backup API.

## Состояние и доказательства

Реальные jobs остаются в workspace/studio/registry.sqlite. Только T00–T12 — в
development/tasks.json. Обновлять через app.development.Journal с expected_hash
и стабильным operation_key. STATUS/HANDOFF генерируются, не редактируются отдельно.
done требует результата, версии и JSON-подтверждения passed для той же задачи/версии.
После прерывания продолжать с сохранённого статуса; не сбрасывать журнал.
Исторический аудит не является тестом текущего кода. job done не означает QA passed;
ready_for_review не означает принятие владельцем. Недоступные метрики — null.
Ошибки/предупреждения сохранять в полном логе, вывод ограничивать с truncated.
После двух неудачных циклов одной проблемы записать blocker и минимальное решение.
