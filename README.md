Настройки описаны в [INSTALL.md](docs/INSTALL.md), формат сценария — в [MULTISHOT.md](docs/MULTISHOT.md), фактические задания — в [current_state.md](docs/current_state.md).

## Состав

- `app/contracts.py`: строгие версионированные схемы ProjectBrief, Task, SourceRef, Claim, ChapterAnalysis, Dossier, ScriptBlock, AudioSegment, ShotPlan, Timeline, QAReport и TaskSubmission. Лишние поля, неверные ID/версии, отрицательные длительности и опасные пути отклоняются.
- `app/registry.py`: единый SQLite-реестр, ревизии, идемпотентность, хеши материалов, ограниченные задания, неизменяемая история результатов, защита `manual/` и `originals/` от автоматической перезаписи.
- `app/library.py`: UTF-8 TXT и текстовый EPUB, сохранение оригинала, порядок разделов, отчёт импорта, SQLite FTS5, чтение по ID, последовательные задачи разбора и проверка ссылок утверждений/досье.
- `app/tts.py`: локальные Piper и Silero, отдельные WAV, фактические измерения, проверка кэша и конфигурации.
- `app/timeline.py`: единый монтажный план и редактируемый MLT для Shotcut; несколько визуальных планов на одну реплику без разрезания WAV. `scripts/render_project.py` запускает тот же движок для экспорта.
- `app/speech_review.py`: проверяемый кэш локального ASR и субтитров; `scripts/preflight_speech.py` позволяет начать проверку речи после сборки, до завершения рендера. Итоговый QA сохраняет все проверки и предупреждения.
- `app/jobs.py`, `app/operations.py`, `app/worker.py`: сохраняемые технические задания, ограниченный набор операций, состояние, отмена и возобновление.
- `app/mcp_server.py`: тонкий локальный stdio-сервер над общими функциями. Облачный сервер и платные речевые API не нужны.

## Запуск ядра на Windows

Нужен Python 3.11 или новее. Из корня репозитория:

```powershell
python -m venv .venv-core
.venv-core\Scripts\python -m pip install -e ".[mcp]"
.venv-core\Scripts\python -m app --workspace workspace doctor
.venv-core\Scripts\python -m unittest discover -s tests -p "test_core.py" -v
.venv-core\Scripts\python -m unittest discover -s tests -p "test_library.py" -v
```

Для CLI без MCP достаточно `pip install -e .`. Команда `studio` после установки эквивалентна `python -m app`. Вывод CLI — JSON; ошибки имеют код и ненулевой код завершения. `doctor` показывает обнаружение инструментов, но не выдаёт его за успешный рендер или прослушивание.

В `examples/contracts/` сохранены правильный и неправильный пример и JSON Schema каждого контракта. Примеры содержат собственные тестовые утверждения; они не являются базой новеллы.

Озвучка использует отдельное окружение с `piper-tts==1.8.0`, локальным `.onnx` и соседним `.onnx.json`. Исполнитель получает путь к модели из конфигурации. Модуль не скачивает модель и не переключается на платный сервис. Для монтажа нужны проверенные Shotcut/MLT; для анализа потоков — FFmpeg/FFprobe. Конкретные версии и фактические проверки сохраняются в отчётах проекта. Установка на чистом компьютере и все ОС не считаются проверенными автоматически.

## Карточка проекта и регистрация материалов

Создайте `workspace/brief.json`:

```json
{
  "schema_version": "1.0",
  "project_id": "pilot",
  "title": "Второй шанс",
  "work_title": "Реинкарнация безработного",
  "character": "Рудеус",
  "language": "ru",
  "milestone": "pilot",
  "target_duration_seconds": 75,
  "source_status": "unavailable",
  "limitations": ["Полный текст новеллы не предоставлен"]
}
```

```powershell
python -m app --workspace workspace init --input brief.json
python -m app --workspace workspace status pilot
python -m app --workspace workspace schema Timeline
python -m app --workspace workspace register pilot visual01 media/scene.mp4 --kind video --rights owned --duration-ms 10000 --revision 1 --key register-visual-01
```

Файл должен уже находиться внутри рабочей папки. `--rights owned` указывается только для собственных материалов; для остальных есть `permission`, `public_domain`, `unknown`. Визуал с `unknown` допускается только для явно включённого `local_review: true`, если в `review_sources` сценария для него указаны URL страницы-источника и непустая атрибуция. Без этих данных он отклоняется. Права остаются `unknown`; это не разрешение на публикацию или распространение. Записи источников и ограничение локального просмотра сохраняются в сборке и пакете. Новый файл/редакция получает новый ID. Во всех изменяющих командах брать текущую `revision` из `status`; числа примеров не универсальны.

## Импорт произведения

```powershell
python -m app --workspace workspace source-import pilot source01 work01 incoming/book.txt --edition "Редакция пользователя" --translation "Указанный перевод" --rights permission --revision 2 --key import-source-01
python -m app --workspace workspace read pilot source01
python -m app --workspace workspace search pilot "имя персонажа" --limit 5
python -m app --workspace workspace analysis-queue pilot source01 --revision 3 --key queue-source-01
python -m app --workspace workspace next-task pilot
python -m app --workspace workspace read pilot source01.chapter0001 --start 0 --length 4000
```

Импорт поддерживает UTF-8 TXT и EPUB с извлекаемым текстом. Сканы и OCR не реализованы. Предупреждения о нумерации/коротких разделах/структуре EPUB видны в отчёте; они не замалчиваются. Полнотекстовый поиск сопоставляет токены и не гарантирует русскую морфологию. Отсутствие результатов не означает отсутствие события. Диапазоны `SourceRef` относятся к извлечённому тексту зарегистрированного раздела; `locator` позволяет найти его в оригинале.

Для полного произведения при импорте нужен явный флаг `--entire-work`; для отрывка его ставить нельзя. `coverage PROJECT_ID` проверяет это заявление, отсутствие блокирующих предупреждений, завершение всех задач глав, неизменность оригинала и сверенное досье с проверенными утверждениями. Это не независимое доказательство полноты издания. После этих проверок карточка обновляется через `brief-update --input brief.json --revision N --key KEY`; статус `source_status: analyzed` без достаточного покрытия отклоняется. Изменение утверждения переводит зависящие от него досье в `needs_review`.

Отдельный рубеж `editorial_review` предназначен для работы по выбранным источникам: он требует `source_status: partial` или `analyzed`, `local_review` и зарегистрированных заметок для фактических блоков. Минимальная фактическая длительность — 45 секунд. Этот режим не завершает анализ всей книги и не снимает требования покрытия, проверенных утверждений и длительности у `full_episode`.

## Файловое задание и передача между клиентами

Задача создаётся через `task-create --input task.json --revision N --key KEY`. Допустимые ответы: ScriptBlock, ShotPlan, ChapterAnalysis, Claim, Dossier. Схему любого ответа можно получить через `schema CONTRACT`.

```powershell
python -m app --workspace workspace task-export pilot analyze.source01.chapter0001 --output exchange/task-001.json
python -m app --workspace workspace task-import --input exchange/response-001.json
python -m app --workspace workspace status pilot
```

Экспорт содержит инструкцию, ограниченный контекст, обе JSON Schema, текущую ревизию и `response_template`. В ответный файл сохраняется заполненный шаблон, а не весь экспортный пакет. Импорт проверяет схему, ревизию, зависимости, существование ID, права и границы материала. Повтор с тем же ключом и содержимым возвращает прежний результат; изменённое содержимое под прежним ключом отклоняется. `validate` проверяет только структуру, не факты и не качество медиа.

## Технические задания

Встроенный демонстрационный комплект регистрируется тем же ядром:

```powershell
python scripts/seed_demo.py --workspace workspace/demo
python -m app --workspace workspace/demo status mushoku_pilot
```

Команда только создаёт карточку и регистрирует собственные иллюстрации, подготовленный сценарий и карточку источников. Она не экспортирует и не принимает ролик. Для производства создать локальный `workspace/demo/runtime.json` с путями `tts_python`, `tts_model`, `ffmpeg_path`, `ffprobe_path`, `melt_path`; для обратной расшифровки дополнительно `asr_python` и имя уже загруженной модели `asr_model`. Параметр `tts_length_scale` необязателен. Эти пути зависят от компьютера и не входят в переносимый пакет.

```powershell
python -m app --workspace workspace run pilot synthesize --input requests/synthesize.json --revision N --key synthesize-01
python -m app --workspace workspace job JOB_ID
python -m app --workspace workspace cancel JOB_ID
python -m app --workspace workspace resume JOB_ID
```

Операции: `synthesize`, `build`, `render`, `qa`, `package`. Параметры используют зарегистрированный ID сценария и ID предыдущих заданий: `{ "script_asset_id": "script01" }`, затем `{ "script_asset_id": "script01", "audio_job_id": "JOB_ID" }`, `{ "build_job_id": "JOB_ID" }`, `{ "render_job_id": "JOB_ID" }`, `{ "qa_job_id": "JOB_ID" }`. Произвольная команда оболочки параметром не является. Итоговые пути и ограничения читать из результата каждого задания.

Для встроенного демо ID сценария — `script_v1`, ID проекта — `mushoku_pilot`; использовать их вместо примерных `script01` и `pilot`. Дождаться `done` предыдущего задания перед следующим. Для правки: `patch PROJECT_ID SCRIPT_ASSET_ID BLOCK_ID --text "Новая реплика" --revision N --key KEY`. Ответ содержит новый ID сценария и список устаревших заданий; оригинал и ручные проекты сохраняются. После правки снова пройти производственные операции с новым ID. Неизменённые WAV повторно используются после проверки хешей.

Для MCP клиент запускает процесс из корня установленного репозитория:

```powershell
.venv-core\Scripts\python -m app.mcp_server --workspace workspace
```

Стандартный вывод этого процесса предназначен протоколу. Наличие сервера не означает, что Claude Code, Gemini CLI или другой клиент уже прошли проверку. Протокольный smoke-тест и реальное испытание конкретного клиента отмечаются отдельно.

## Проверка результата

Проверяемый артефакт — настоящий MP4 и открываемый MLT с нужными медиа, отдельными WAV, субтитрами, сценарными блоками и отчётом. Непроведённые визуальные, слуховые и фактические проверки сохраняются как `not_checked`. Отчёт относится к конкретной сборке и хешу. `ready_for_review` не означает принятие пользователем; `accepted` требует явного принятия человеком.

В тестах используются собственные маленькие тексты и временные папки, включая кириллицу и пробелы. Проверены отказ от выдуманных ID, опасных путей, неверных версий и длительностей; повторы и конфликты ревизий; сохранность ручных правок; TXT/EPUB, FTS, последовательность задач и ссылка на точную редакцию. Результаты рендера, озвучки, переноса, MCP и совместимости с редактором следует читать в фактических отчётах текущего проекта, а не выводить из существования кода.

Полный анализ «Реинкарнации безработного» и рубеж `full_episode` не объявляются завершёнными. Редакционный выпуск v3 экспортирован, прошёл технический QA и упакован для просмотра; прослушивание и принятие пользователем остаются открытыми. Независимый пользователь, все клиентские среды и удобная панель также не объявляются проверенными или готовыми.

## GitHub и перенос на другой компьютер

Git хранит исходники, тесты, конфигурацию production, примеры и документацию.
Локальные `workspace/`, реестр SQLite, отдельные WAV и кеш, Timeline/MLT,
оригиналы, ручные правки, готовые видео, модели и установленные инструменты
остаются на этом компьютере и исключены из Git. Клон репозитория не восстанавливает
существующие выпуски: для них нужна отдельная резервная копия этих каталогов.
Не копировать активную SQLite поверх другой базы; использовать SQLite backup API.

Начало разработки: прочитать `AGENTS.md`, `development/HANDOFF.md`,
`development/tasks.json` и только нужную задачу плана. Текущие интерфейсы:
[development/INTERFACES.md](development/INTERFACES.md).
Профиль `config/production_profile.json` задаёт технические предпочтения;
локальный `runtime.json` задаёт пути. Не менять голос Ruslan и не синхронизировать
профиль автоматически. Перед производством проверить согласованность окружения.

Дополнительные модули: `app/ai_accounts.py` управляет локальными профилями клиентов,
`app/ai_cli_runtime.py` — их запуском, `app/multi_ai*.py` — интерфейсом нескольких ИИ,
`app/production_bridge.py` — связью со студией. `app/development.py` ведёт журнал,
`app/project_memory.py` и `app/code_map.py` обслуживают знания и карту кода.
`knowledge/` содержит заметки и Canvas, `development/` — план и состояние задач,
`scripts/` — установку и вспомогательные операции, `tests/` — проверки.

Секреты вводятся через штатную локальную авторизацию клиентов и не коммитятся.
Перед каждым push проверять `git diff --cached --stat` и список staged-файлов.
Не отправлять служебные `refs/codex/*` через `--mirror` или `--all`;
отправлять только проверенную ветку и конкретный тег. Git-тег фиксирует версию
исходников, а не резервную копию производственных данных.
