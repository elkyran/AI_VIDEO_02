## 0. Как пользоваться планом

Работать в существующем `AI_VIDEO_02`. Не создавать студию заново. Выполнять четыре пакета по порядку: A → B → C → D. Первый запуск ограничен пакетом A. После каждого пакета сохранить состояние, сообщить результат и остановиться. Следующий пакет запускается короткой командой владельца.

Это границы рабочих сессий, а не повод заново исследовать проект. Прочитать правила и оглавление один раз; затем извлекать только текущую задачу. Не копировать весь план в `AGENTS.md`, карточки, каждый запрос или каждый отчёт.

- Один управляющий агент; не создавать подагентов и не менять глобальные настройки клиента. Обычные локальные процессы могут выполняться параллельно.

- После двух неудачных циклов исправления одной проблемы остановиться: сохранить причину и минимальное следующее действие. Не повторять один и тот же запуск без новой проверяемой гипотезы.

- Никаких `git reset --hard`, `git clean`, массовых удалений, перезаписи ручных файлов, отключения защит или публикации репозитория.
- Установка Graphify разрешена только из указанного официального проекта в изолированное окружение. Не обновлять зависимости озвучки ради Graphify. Системные права и несовместимые изменения — отдельная блокировка, не обход ограничений.

### T04 — Разделить кеш ASR и проверку соответствия

**Зависимость:** T03. **Адресная область:** `app/speech_review.py`, связанные тесты. Строка 169 — подсказка из аудита, не постоянный адрес.

Разделить два результата:

- Распознавание: ключ зависит от содержимого реально распознаваемого WAV, модели/версии ASR, языка, параметров декодирования, VAD/предобработки, значимых параметров вычисления и версии схемы кеша. Не зависит от картинок, ID выпуска или визуальных полей манифеста.
- Проверка соответствия: использует результат ASR, ожидаемый произносительный текст, правила сопоставления и необходимые тайминги. При изменении текста/привязки эта проверка обновляется, даже если звук прежний.

Не менять рабочий TTS-кеш. Ввести версию нового ASR-кеша; старый оставить до проверки. Повреждённая/неполная запись не считается попаданием. Не делать опасной миграции «на месте».

**Тесты:** прежний WAV + новая картинка → нет нового ASR; новый WAV → ASR; прежний WAV + новый ожидаемый текст → только новая сверка; другая ASR-модель/предобработка → ASR; неполный кеш → безопасная ошибка или пересчёт. Использовать подменённый распознаватель и исторические результаты; не загружать новую модель ради unit-теста.

**Приёмка:** тесты пройдены; пример v3/v4 из аудита объясняется новым ключом; не заявлять об измеренной экономии GPT по времени локального ASR.
**Откат:** переключение на прежнюю версию ключа без удаления данных.

Хранить новый результат отдельно, не перезаписывать ручной MLT. Повтор того же запроса должен распознавать существующую операцию по стабильным входам.

**Приёмка:** короткий локальный технический пример 10–30 секунд; проверка декодирования, времени, окончаний и ссылок MLT. Сохранность видео подтверждать идентичностью видеопакетов/меток или эквивалентным проверенным методом, не равенством хеша всего MP4. Локальные заглушки/синтетические материалы допустимы; полный выпуск не запускать.
**Откат:** старые скрипты и прежняя версия результата остаются доступны.

### T06 — Исправить барьер готовности и упаковку последней версии

**Зависимость:** T05. **Область:** QA, упаковка, связывание финального артефакта с выпуском.

Не смешивать `job.state=done`, успешность QA, редакционную проверку и принятие человеком. Завершённый job с `quality_status=blocked` не разрешает финальную передачу как проверенную. `not_checked` не превращается в `passed`.

Финальная упаковка должна явно брать утверждённый ID версии, в том числе после замены голоса. Манифест связывает видео, MLT, аудио и зависимости с этой версией. Старый ZIP нельзя выдавать за архив нового Ruslan только потому, что он имеет удобное имя.

Сохранить проверки источников, соответствия сцен, отрицаний, окончаний, синхронизации, длительности, декодирования и зависимостей. Повтор неизменного результата допустимо пропустить только с подтверждением актуальности. После изменения связанного итогового файла выполнить соответствующий финальный контроль.

**Приёмка:** тест `done + blocked`; тест отсутствующей зависимости; тест выбора старого архива; тест неизвестной редакционной проверки. Правильный путь сохраняет разделение `ready_for_review` и `accepted`.
**Откат:** обратимая версия логики финализации; не исправлять старые отчёты задним числом.

**Остановка после B:** отчёт об исправлениях и проверках. Следующая задача T07; третий ролик не создавать.

### T07 — Создать Markdown-память и карточки возможностей

## 5. Состав игрового дерева: 32 возможности

Это каталог возможностей, не дополнительный список обязательных реализаций. Статусы заполнить по фактам. Для неиспользованной полной библиотеки — `partial/unknown` по коду и `not_checked` либо историческое ограничение, не `production_verified`.

| Ветка | Узлы первой карты |
|---|---|
| Источники | `SRC-IMPORT` импорт; `SRC-CLAIMS` события/доказательства; `SRC-DOSSIER` досье; `SRC-SEARCH` поиск по произведению |
| Сценарий | `SCR-BRIEF` тема; `SCR-STRUCTURE` аргументация; `SCR-BLOCKS` блоки; `SCR-REVIEW` факты/редактура |
| Аудио | `AUD-PROFILE` голос диктора; `AUD-PRONUNCIATION` имена; `AUD-WAV` фрагменты; `AUD-ASR` распознавание; `AUD-ALIGN` сверка/синхронизация; `AUD-REPLACE` замена звука; `AUD-MIX` музыка; `AUD-CHARACTERS` будущие голоса персонажей |
| Визуалы | `VIS-CATALOG` архив; `VIS-SEARCH` поиск кандидатов; `VIS-MATCH` смысловое соответствие; `VIS-PREP` подготовка клипов/панелей |

На главной карте показывать первые два типа и немного важных связей; подробные ссылки хранить внутри заметки. Не превращать близость узлов на картинке в техническую зависимость.

Будущий узел `AUD-CHARACTERS` требует разметки говорящего, разрешённых голосов и проверок, но это не блокирует нынешний рассказ одним диктором. Связи между областями не должны создавать ложные обязательные препятствия для уже работающего выпуска.

## 7. Общая приёмка и контроль потерь качества

Рабочая студия не должна зависеть от открытого Obsidian, наличия Graphify или аккаунта конкретного ИИ. Эти инструменты помогают разработке и навигации; их отказ не должен уничтожать результаты или запрещать старые команды.

Необходимо подтвердить: старые интерфейсы сохранены; задачи возобновляются; один и тот же вход не запускает незаметно вторую дорогую операцию; звук не распознаётся повторно из-за новой картинки; полная книга не объявляется прочитанной по выборочным источникам; неверные/непроверенные статусы не выглядят успешными; ручная раскладка и монтаж не перезаписываются; каждый статус имеет происхождение.

Реальная экономия качества-сопоставимого полного выпуска подтверждается следующим обычным роликом, а не только тестом карты. Его создание — отдельное задание владельца после этого плана.
