## Решения интеграции

- Старые `studio.cmd`, `app.cli`, `jobs`, `operations`, TTS и production profile
  остаются точками существующего производства. Новый запуск включается явно.
- FastAPI/React не установлены; stdlib HTTP + локальные HTML/JS позволяют проверить
  интерфейс без установки пакетов или внешних CDN. Публикации/сервера в интернете нет.
- Рабочий production Registry уже пригоден для хранения. Новые таблицы имеют префикс
  `ai_`; в этом пакете они создаются только в изолированном development workspace.
  Производственный `workspace/studio/registry.sqlite` читается через mode=ro.
- Источник технических предпочтений — прежний production profile. Низкое разрешение
  технической fixture является явной настройкой теста, а не изменением профиля.
- Текущие назначения writer=Codex, director=Codex, critic=Gemini остаются
  переназначаемыми ролями. Недоступный Gemini заменяется только явно выбранным
  режимом GPT-only с обозначенной самопроверкой. Версия модели остаётся `null`,
  если не получена из подтверждённого источника. Реальный доступ подтверждается
  отдельным принятым ответом; исторические доказательства GPT-1…3 сохранены.
- CLI-подключения и автоматическая ротация fail closed: отсутствие проверки не превращается
  в разрешение. FakeAdapter проверяет алгоритмы без запросов провайдерам.
- Obsidian хранит решение и ссылки, Graphify помогает навигации. Ни один из них не является
  очередью, хранилищем аккаунтов или обязательным работающим процессом.

## Контроль сохранности и откат

Перед изменениями сохранены хеши исходников, логический отпечаток реестра, ZIP исходников
и SQLite backup API snapshot в `reports/development/2026-10-18_MULTI_AI`.
Git изначально без коммитов; создана ветка `codex/multi-ai-offline`, версия определяется
SHA-256 исходников. Пользовательские untracked-файлы не добавляются в коммит автоматически.

Для отключения закрыть только новый launcher и продолжить `studio.cmd`. Новые модули
изолированы. Восстановление через baseline — только сравнением конкретных файлов,
без reset/clean и без замены более поздних правок пользователя. Реестр production
восстанавливать не требуется, если итоговая проверка сохранности прошла.
