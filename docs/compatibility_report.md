Установленный для MCP отдельный `.venv-core` использует Python 3.11, Pydantic 2.12.5, MCP 1.30.0 и NumPy 2.4.3. Озвучка использует отдельную среду; наличие SDK не подтверждает доступность речевой модели.

Воспроизводимые проверки из корня репозитория:

```powershell
.\.venv-core\Scripts\python.exe -m unittest discover -s tests -p test_mcp.py -v
.\.venv-core\Scripts\python.exe -m unittest discover -s tests -p test_jobs.py -v
.\.venv-core\Scripts\python.exe -m unittest discover -s tests -p test_timeline.py -v
```

При первоначальной проверке прошли один интеграционный тест MCP, шесть тестов очереди и два теста нативного монтажа. Более поздние целевые прогоны, CUDA, многоплановый монтаж и актуальный QA v3 перечислены в [TESTING.md](TESTING.md); это отдельная история результатов. Тест очереди запускает реальный MLT-рендер из короткоживущего клиентского процесса, завершает клиент и проверяет, что отдельный исполнитель создал действительный MP4 с видео и звуком. Проверки отказов охватывают неизвестные операции, неверные параметры, отсутствующие ID, конфликт версии, отмену, предел повторов, изменённый MLT и недоступную локальную возможность. Правка реплики сохраняет исходный сценарий, неизменённый аудиофайл в кэше и ручной проект, помечая зависимые задания устаревшими.

Нативный тест проверяет 1920×1080, 30 кадров/с, два аудиосигнала на разных дорожках, относительные ссылки и повторный экспорт. Его двухсекундный исходник — технический тестовый материал, а не обещанный пилот продолжительностью 45–90 секунд.

Сервер запускается только по stdio; корневая рабочая папка задаётся до начала сессии:

```powershell
.\.venv-core\Scripts\python.exe -m app.mcp_server --workspace workspace
```

Инструменты не принимают произвольный shell-код, XML, установку программ, публикацию или произвольную рабочую папку. Ограничения API не являются изоляцией операционной системы: сервер имеет права своего процесса.
