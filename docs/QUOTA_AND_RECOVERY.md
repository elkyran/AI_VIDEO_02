# Квота и восстановление

Существующая очередь хранит attempts, immutable accepted result, event log и CAS
в SQLite. V2 хранит только run brief/key в ai_v2_runs и нормализует статусы.
Один provider/profile выполняет одну задачу, local_heavy — максимум одну.
Автоматическая ротация принудительно выключена; квота хранится как наблюдение,
отсутствующие usage/model/reset значения — null.

Quota failure отображается WAITING_QUOTA. Независимые задачи исходного scheduler
могут продолжиться, зависимые ждут accepted result. Ошибка auth → WAITING_AUTH.
Сетевые сбои используют существующий ограниченный backoff; fake задачи v2 имеют
max_attempts=2. `advance` — явное разрешение продолжить очередь после исправления
условий; это не гарантия восстановления квоты и не переключение аккаунта.

При штатном закрытии/перезапуске результаты completed повторно не вызываются.
Незавершённый FakeAdapter помечается interrupted, затем повторяется с теми же
входными версиями. Проводился restart процесса, а не выключение Windows.
Существующий LiveCLIAdapter имеет recovery для своего дочернего процесса;
новый live agy route и восстановление render ещё не интегрированы.

Сцены меняются через существующие update_scene/invalidate_scene с версией;
это делает зависимые результаты stale. Удалённая команда «переделать сцену» в v2
пока NOT_IMPLEMENTED: не запускайте весь production ради обхода отсутствующей
команды. Тесты старой очереди проверяют late/stale rejection и лимиты.
После двух неудачных циклов одной проблемы фиксировать blocker, не ослаблять QA.
