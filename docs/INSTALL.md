# Установка и локальные среды

Проверенная среда разработки: Windows 11 x64, Python 3.11.9, Shotcut 26.9.27. Код требует Python 3.11 или новее; работа всех зависимостей на каждой более новой версии Python не проверена. Для повторения текущего результата выбирайте Python 3.11 x64. Установка на другом, чистом компьютере пока **не проверена**.

Команды ниже запускаются из корня репозитория. Сценарий определяет корень относительно собственного файла, поэтому личных путей автора в нём нет. Он не требует ключей API, платного сервиса озвучки, аккаунта Hugging Face или токенов.

## 1. Диагностика без изменений

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
```

Без флагов установки сценарий только проверяет пути и версию Python. Он не создаёт окружения, не устанавливает пакеты, не скачивает модели, не пишет `runtime.json` и не запускает производство. `ExecutionPolicy Bypass` действует только для этого процесса; системная политика не меняется.

Если Python не найден, установите Python 3.11 x64 самостоятельно. Можно явно передать путь к своему `python.exe`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Python 'D:\Programs\Python311\python.exe'
```

Путь в примере заменяется на фактический путь вашего компьютера. Диагностика наличия файла не доказывает успешный синтез или экспорт.

## 2. Явная установка зависимостей

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -Install
```

Этот флаг разрешает сетевую установку из PyPI. Создаются две отдельные среды без доступа к системным пакетам:

| Среда | Назначение | Зафиксированные основные версии |
|---|---|---|
| `.venv-core` | CLI, SQLite, схемы, задания, MCP, подготовка медиа | `pydantic==2.12.5`, `numpy==2.4.3`, `mcp==1.30.0` из `pyproject.toml` |
| `.venv-tts` | Piper и автономное распознавание Whisper | `piper-tts==1.8.0`, `faster-whisper==1.2.1`, `onnxruntime==1.24.4`, `numpy==2.4.4` и остальные версии из `requirements-tts.txt` |

Существующие окружения не удаляются и не пересоздаются. Повторный `-Install` снова вызывает pip с объявленными зависимостями; обычная диагностика этого не делает. Установщик сохраняет фактические списки пакетов в `downloads/core-freeze.txt` и `downloads/tts-freeze.txt`. Это фиксация установленного окружения, а не полный проверенный lock-файл для всех платформ. Сборочные и не перечисленные транзитивные зависимости могут разрешаться отдельно.

Текущая рабочая `.venv-tts` была создана с доступом к системным пакетам при разработке. Новый сценарий намеренно создаёт изолированную среду. Именно этот чистый путь ещё предстоит проверить на другом компьютере; существование списка версий такой проверки не заменяет.

## 3. Явная загрузка голоса и монтажного движка

Для текущего личного некоммерческого пилота:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -DownloadVoice -Voice ruslan -DownloadShotcut
```

Альтернативный голос:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -DownloadVoice -Voice denis
```

`-DownloadVoice` загружает `.onnx`, соседний `.onnx.json` и карточку модели из официального репозитория [Piper voices](https://huggingface.co/rhasspy/piper-voices). Версия репозитория закреплена: `c10ece1aade47bb51c153c893d14e5bf8e5b7117`. Каждая голосовая модель занимает около 63 МБ. У Ruslan карточка датасета указывает CC BY-NC-SA 4.0, у Denis — CC0. Подробности и ссылки находятся в [LICENSES.md](LICENSES.md).

`-DownloadShotcut` загружает официальный Windows x64 ZIP [Shotcut 26.9.27](https://github.com/mltframework/shotcut/releases/tag/v26.9.27), около 203 МиБ, и распаковывает его в `tools/Shotcut`. Уже существующая папка Shotcut не перезаписывается. Используются входящие в этот комплект `melt.exe`, `ffmpeg.exe` и `ffprobe.exe`; отдельная случайная сборка FFmpeg не требуется.

Для голоса и Shotcut ожидаемые SHA-256 сохранены в сценарии и сверяются до использования. Рядом с файлами создаются `.sha256`, а журнал источников и проверок записывается в `downloads/verified-downloads-*.json`. Существующий файл с другим хешем не заменяется автоматически. Неполная загрузка остаётся с окончанием `.download` для диагностики.

## 4. Явная подготовка локального распознавания

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -DownloadAsr
```

Этот отдельный флаг использует установленную `.venv-tts` и загружает публичную модель [Systran/faster-whisper-medium](https://huggingface.co/Systran/faster-whisper-medium), примерно 1,5 ГБ, в `models/asr/medium`. Закреплена ревизия `08e178d48790749d25932bbc082711ddcfdfbc4f`. После загрузки записывается `download_checksums.json` с SHA-256 файлов. Эти хеши являются записью полученных файлов, а не независимой заранее заданной контрольной суммой издателя.

Рабочий ASR-модуль не скачивает отсутствующую модель. По умолчанию он использует CPU `int8`; CUDA включается явно через настройки ниже. В обоих режимах действует `local_files_only=True`. Можно настроить уже имеющийся локальный каталог вместо повторной загрузки. Если в `runtime.json` указан просто `medium`, требуется готовый пользовательский кэш Hugging Face; переносимость такого кэша автоматически не обеспечивается.

## 5. Конфигурация конкретного компьютера

После подготовки нужных файлов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1 -WriteRuntime -Workspace workspace/demo -Voice ruslan
.venv-core\Scripts\python.exe -m app --workspace workspace/demo doctor
```

Создаётся `workspace/demo/runtime.json`. Если файл уже существует, установщик останавливает именно запись конфигурации и предлагает отредактировать его вручную. Он не заменяет сохранённые пути. `-Workspace` должен указывать папку внутри репозитория.

Поля конфигурации:

| Поле | Значение |
|---|---|
| `tts_python` | Абсолютный путь к `.venv-tts/Scripts/python.exe` |
| `tts_model` | Абсолютный путь к выбранному `.onnx`; `.onnx.json` должен лежать рядом |
| `tts_length_scale` | `1.08` для текущего теста; большее значение замедляет речь |
| `tts_engine` | `piper` по умолчанию; `silero` включается явно с локальной `.pt` моделью |
| `tts_speaker` | Для Silero: `aidar` в проверенном варианте |
| `tts_sample_rate`, `tts_cpu_threads` | Для Silero: `48000` и `4` |
| `tts_max_chars`, `tts_paragraph_silence` | Для Silero: `950` символов и `0.14` секунды только между отдельно синтезированными абзацами/предложениями |
| `ffmpeg_path`, `ffprobe_path`, `melt_path` | Абсолютные пути к исполняемым файлам установленного Shotcut |
| `asr_python` | Python с установленным `faster-whisper` |
| `asr_model` | Абсолютный путь к локальной модели или имя уже закэшированной модели |
| `asr_device` | `cpu` по умолчанию; `cuda` включается явно |
| `asr_compute_type` | `int8` по умолчанию; в текущей CUDA-среде проверен `int8_float16` |
| `asr_dll_directories` | `[]` по умолчанию; на Windows список существующих абсолютных каталогов нужных CUDA/cuDNN DLL, подключаемых только для процесса ASR |
| `video_encoder` | `libx264` по умолчанию; `h264_nvenc` после фактической проверки местного GPU |
| `render_threads` | Целое число от 1 до 16, по умолчанию 1; в текущей среде проверено 4. Передаётся MLT как отрицательное `real_time`, без пропуска кадров |

Поля `asr_python` и `asr_model` записываются автоматически только при наличии `models/asr/medium/model.bin`. Иначе их можно добавить вручную после подготовки модели. Необязательные настройки GPU и потоков выбираются отдельно. Конфигурация содержит пути этого компьютера; она не является переносимым файлом проекта и не включается в пользовательский пакет результата.

Для ASR допустимы явные типы вычислений `int8`, `int8_float16`, `int8_float32`, `int8_bfloat16`, `float16`, `float32`, `bfloat16`; работоспособность конкретного сочетания зависит от оборудования и установленного CTranslate2. Исполнитель проверяет фактически полученные устройство и тип вычислений. Отсутствующие DLL, неподдерживаемый GPU или другой фактический режим приводят к ошибке, а не скрытому переходу на CPU или загрузке модели. Автоматическая установка CUDA/cuDNN этим сценарием не выполняется. Устройство, тип вычислений и DLL-настройки входят в идентичность кэша речи.

На текущем компьютере подтверждены CUDA/int8_float16 для локального `medium` и полный предварительный ASR 47 реплик. Это не проверка чистой установки на любом GPU. Четыре сравнительных экспорта подтвердили целостность кадров при `render_threads: 4`; тёплое ускорение в данном фрагменте составило около 8–14%, зависит от проекта и нагрузки. Подробные измерения — в [TESTING.md](TESTING.md).

### Дополнительный режим Silero

Режим использует уже подготовленный `models/silero/v4_ru.pt`, соответствующий ему `manifest.json` и локальный PyTorch. `setup.ps1` остаётся установщиком Piper и не скачивает Silero или PyTorch. В текущей среде проверены `torch==2.5.1+cu121`, `numpy==2.4.4`, Python 3.11 и синтез Silero на CPU. Уже установленный PyTorch повторно устанавливать не нужно.

Для отдельной чистой среды пользователь может явно установить CPU-вариант по [официальной инструкции PyTorch 2.5.1](https://pytorch.org/get-started/previous-versions/):

```powershell
.venv-tts\Scripts\python.exe -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
```

Эта команда требует сети и здесь не запускалась. Чистый CPU-пакет на другом компьютере ещё не проверен. Источник весов указан в `models/silero/manifest.json`; текущие веса размером 40 107 184 байта были скопированы из имеющегося локального кэша. Их SHA-256 фиксирует именно использованный файл и не выдается за независимую контрольную сумму издателя.

В конфигурации нужны `tts_engine: "silero"`, `tts_model` с абсолютным путём к `.pt`, `tts_python` с путём к Python, где установлен PyTorch, и `tts_speaker: "aidar"`. Остальные настройки из таблицы имеют указанные значения по умолчанию. `tts_length_scale` относится только к Piper. Для Silero не выполняется скрытый переход на другой голос или сетевую службу.

Один законченный абзац до лимита передаётся модели целиком; запятые, двоеточия и тире не запускают новый вызов синтеза. Длинные абзацы делятся по консервативно найденным границам предложений; слишком длинное отдельное предложение вызывает ошибку вместо обрезки. Для сценариев предпочтительны короткие законченные абзацы. Все сэмплы и окончания сохраняются, уровень меняется одним коэффициентом на блок. Метаданные содержат границы фактических вызовов и число обрезанных сэмплов.

## 6. Проверка перед производством

```powershell
.venv-core\Scripts\python.exe -m unittest discover -s tests -p "test_core.py" -v
.venv-core\Scripts\python.exe -m unittest discover -s tests -p "test_library.py" -v
.venv-tts\Scripts\python.exe -m unittest discover -s tests -p "test_tts.py" -v
.venv-core\Scripts\python.exe -m unittest discover -s tests -p "test_asr.py" -v
```

Интеграционный TTS-тест реально синтезирует короткие фразы при наличии Piper и локального Denis. Если установлен только Ruslan, этот тест помечается `skipped`, а не успешным. Отдельный интеграционный тест Silero выполняется при наличии PyTorch и `models/silero/v4_ru.pt`; он проверяет целый абзац и инвалидирование кэша при изменении текста, настроек и WAV. Тесты ASR проверяют метрики и временные метки без загрузки модели; проверка распознавания настоящего WAV выполняется отдельным заданием `qa`.

Реальное производство выполняется через `synthesize → build → render → qa → package` и сохранённые задания; команды описаны в [README](../README.md) и [WORKFLOW](../WORKFLOW.md). Установщик этот процесс не запускает. Изменение сценария должно пройти через новую версию и новую озвучку, а не через ручную замену зарегистрированного файла.

В Windows библиотеке Piper требуется обход для некоторых путей с кириллицей: модуль копирует поставляемые данные espeak в ASCII-путь временной папки. Модели и проект остаются на своём месте. Если сама временная папка содержит не-ASCII символы, требуется явно задать подходящий `espeak_data_dir`; такая конфигурация другого пользователя ещё не испытывалась.

## Что проверено у установщика

В текущей среде проверены синтаксический разбор PowerShell, запуск по умолчанию без установки и скачиваний, создание отдельной тестовой runtime-конфигурации и отказ от её перезаписи с сохранением хеша. Ветки новой установки, новых сетевых загрузок и перенос на чистый компьютер не объявляются испытанными. Голоса, ASR и Shotcut отдельно запускались в рабочей среде; точные результаты находятся в отчётах соответствующих заданий. Совместимость со всеми ИИ-клиентами и всеми операционными системами не заявляется.
